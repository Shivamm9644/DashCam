# Architecture, schema and contracts

## Deployment shape
Modular monolith for the control API, plus separately supervised TCP gateway and bounded media worker. Start on one appropriately measured VPS with separate processes/containers. PostgreSQL for durable state and durable job/outbox tables, S3-compatible private object storage for finalized media, bounded local spool for live/temporary bytes. Add Redis only when measurements justify it. No Kubernetes, Kafka or microservice fleet for MVP.
React + TypeScript frontend; Node.js + TypeScript API/adapters if compatible with existing source; PostgreSQL. Retain working JavaScript protocol modules behind typed interfaces instead of rewriting them. Pin supported dependency versions at implementation and record lockfiles. Docker Compose staging with TLS reverse proxy, rotation and disk limits. Public TCP device ports are separate from HTTPS; ordinary HTTP reverse proxies do not automatically handle them.
Prior project context suggests JT808 TCP 7800, JT1078 TCP 10780 and HTTP 3000, but M0 MUST verify actual code/config. Do not expose development HTTP publicly. Browser video needs a gateway compatible output: HLS first, latency disclosed; WebRTC later if needed. Browsers cannot directly play a JT1078 TCP stream.

## Flow
Camera -> existing protocol gateway -> normalized telemetry/event adapters -> durable deduplication/outbox -> PostgreSQL and media jobs. Gateway acknowledges messages according to protocol semantics; never falsely claims durable persistence. API -> tenant/assignment authorization -> command service -> active terminal connection. Device capabilities gate requested commands. Media worker -> validated bounded spool -> private object -> ready metadata. Client requests authorized short-lived media URLs, with authorization again on refresh. WebSocket rooms are tenant/assignment scoped, and access is rechecked after reassignment/revocation.

## Protocol audit deliverables
Inventory listeners, packet parsers, checksums/escaping, device IDs/serials, registration/authentication, heartbeat, GPS and alarm normalization, command encoder/ACK matching, JT1078 framing/reassembly, codec handling, simulator fixtures and persistence. Capture baseline fixtures and test unchanged parser behavior before adapting. Verify live-start/stop (including existing 0x9101 support if present), ACK timeout, channel selection, audio payload codec, SD playback/event retrieval and alarm clip upload. Do not assume historical recording support from live-start support. Capability matrix per model/firmware: confirmed/unsupported/unknown, evidence, date and limitations.

## Data model
Core: tenants, branches, users, roles, permissions, user_roles, customer_device_access, vehicles, drivers, vehicle_driver_assignments, devices, device_models, protocol_profiles, device_credentials, device_assignments, camera_channels, device_sessions, capability_profiles.
Commercial: plans, plan_versions, entitlements, subscriptions, device_licenses, retention_policy_versions, usage_periods, quota_reservations, usage_entries.
Operational: telemetry_points (time partitions), latest_positions, trips, trip_daily_summaries, events, event_media_links, media_objects, live_sessions, device_commands, command_attempts, geofences, alert_rules, notifications, audit_logs, job_queue, outbox.
Tenant-owned tables have tenant_id; composite foreign keys prevent cross-tenant linking. Scope by server-derived tenant. Telemetry uniqueness includes tenant, device, source sequence/timestamp policy; sequence wrap and device reboot are handled, not blindly deduped forever. Store received_at and device_time separately, preserve original timezone/source and normalized UTC. Track clock skew, validity and stale GPS. Never swap lat/lon silently.
Assignment records are effective-dated. Historical records retain original tenant ownership after transfer. New tenant cannot see old tenant media/history. Implement transactional transfer with active stream stop, socket-room revocation, URL expiry considerations, pending command cancellation and no overlapping assignments. Use short URL lifetime (e.g. 60s); already downloaded copies cannot be revoked.
Media metadata: object key, bytes, hash, codec, channels, start/end timestamps, audio availability, actual pre-roll, state, expires_at, quota reservation and deletion reason. Object keys use server-generated IDs, never user filenames or public sequential paths.
Events: source alarm, normalized type, severity, device time, received time, location validity, dedupe key, status, clip availability and reason. States include detected, pending-media, uploading, processing, ready, failed, quota-blocked, unsupported and expired; transitions idempotent and observable.

## API surface (version /api/v1)
Auth login/refresh/logout/reset; /tenants; /users; /roles; /masters/{allowed-resource}; /devices; /devices/{id}/assignments; /devices/{id}/capabilities; /vehicles; /positions/latest; /devices/{id}/history; /trips; /events; /events/{id}/media; /media/{id}/playback-url; /live-sessions create/status/stop; /commands create/status; /usage; /subscriptions; /reports; /audit.
Generate OpenAPI schema, pagination, indexed date-range limits, standard error envelope, request IDs, idempotency keys for consequential commands and exports. Server validates enum/resource allowlists; no unrestricted generic table editor. Long reports are asynchronous, tenant scoped and expire. Media/live creation checks subscription, capability, quota and permissions before dispatch.

## Security and operations
Hash passwords securely; rotating/revocable sessions, rate limits, secure cookie or documented token design, CSRF protection where applicable, platform-admin MFA, least privilege, secret management and no credentials in source/logs. Device identification alone is not authentication: reuse real credential mechanism; legacy insecure hardware requires documented compensating controls. Validate every binary length before allocation; enforce socket connection, reassembly memory, timeout and upload size bounds. Spawn FFmpeg with argument arrays, never shell-interpolated device data. Private storage, TLS browser access, auditable microphone enablement and export. Do not place signed media or GPS responses into public/PWA caches.
Daily encrypted off-host DB backup plus WAL/PITR if budget supports it; MVP proposed RPO 24h/RTO 4h must be validated by restore rehearsal. Backups expire on a documented schedule (proposed 7 daily + 4 weekly); expired user data may remain in backups until rotation and must not reappear on restore. Lifecycle and deletion jobs use mark -> delete -> verify/retry -> finalize. Reconcile orphan objects and failed quota reservations. Do not back up disposable live segments. Health endpoints separate API, device gateway, queue, DB and media worker. Alert on disk, CPU, reconnect rate, queue age, ingestion gaps, cleanup failures and spend.
