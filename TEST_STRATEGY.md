# Test strategy
The companion TEST_CASES.csv contains scenario definitions, not executed results. Initial status NOT_RUN. Antigravity must expand each into an automated integration/E2E test or attach manual hardware evidence, with actual outcome, timestamp, build and artifacts. Fake protocol tests do not establish real-device compatibility.

## Environment and deterministic seeds
Separate test tenant/database/bucket and test-only devices. Never send simulator commands to production cameras. Seed 3 tenants, 20 customers (8/6/6), one Admin each, one Super Admin and 30 devices (12/10/8); assign some customers multiple devices and some no devices. Include 2 branches per tenant, duplicate vehicle labels in different tenants, 2-channel device, silent/no-audio model, unsupported codec model, SD-enabled model and model without historical retrieval. Use deterministic random seed 20261022 and simulated UTC times with Asia/Kolkata plus DST-observing timezone display tests. Mark synthetic recordings clearly.

Generate 30 days/device of GPS, stopped/moving periods, cross-midnight trips, GPS jumps, out-of-order/offline backfill, ignition events and event storms. Time-travel retention/subscription tests rather than waiting a month. Normal scenario: 5 events/day, 30-second clips; heavy scenario: 20/day, 2 channels and failed retries. Record generated row and byte counts. Include clean, noisy, delayed and invalid binary fixtures from the M0 baseline.

## Layers and tools
Unit tests for normalization, quota math, permissions, retention cutoff and trip calculations. PostgreSQL-backed integration tests for tenant relations, idempotency, atomic reservations, jobs/retries and transfer. Binary socket fixture replay for gateway fragmentation and reconnection. FFmpeg/ffprobe checks for media duration/codec/audio and corrupt files. Playwright browser E2E for all roles, map filters, live timeout, audio toggle and export permissions. k6 or equivalent for HTTP and a socket harness for device/video load. Pin tools during implementation and store commands/results. Manual hardware matrix for every promised model/firmware/channel/codec.

## Load profiles and proposed acceptance targets
Run 100, 500 then 1,000 simulated telemetry devices with GPS intervals from policy, including a 10x burst after network restoration. Video load is separate: 1/5/10 concurrent live channels and 1/5/10 concurrent clip jobs with realistic bitrate, then cap at measured safe threshold. No claim of 1,000 simultaneous video streams. Record device connections, points/s, API latency, CPU, RAM, disk I/O, DB growth, media throughput, packet loss and monthly extrapolated cost.
Proposed gate on declared hardware: ordinary API p95 <=500ms excluding external maps/media; GPS receive-to-browser p95 <=5s when online; live HLS startup <=15s under supported keyframe cadence; event ready <=60s after complete upload at normal load; no unbounded memory/disk growth during 24h soak. If device/network cannot meet target, document measured limits and revise product promises explicitly. Run a 72h real-device pilot after lab soak. Inject 5-minute DB/object-store outages, restart gateway mid-frame and disk high-water; prove bounded recovery and no cross-tenant visibility.

## Release gate
All mandatory cases executed; P0/P1 zero open; no tenant data leakage; real-device event/live/audio supported or explicitly disabled; quotas and deletion verified with actual objects; one restore drill; dependency/security checks triaged; no secrets in repo; measured monthly cost and capacity documented; operator can roll back app and compatible migrations. Record failures as failures with reproduction steps, never change expected output to hide them.
